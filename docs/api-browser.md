# ブラウザでAPIの一覧を見て、実際に試す

このページは、APIを初めて試す人向けの手順です。
操作するのは**VS Codeと普段のブラウザ**です。Postmanなどの追加アプリは不要です。

## 何ができる？

[API一覧・動作確認](http://localhost:8787/docs/api)を開くと、次を確認できます。

- どんなAPIがあるか（19操作）
- 何を入力するか、ログインが必要か
- 実行すると何が返るか
- 実際に自分のPCのAPIへ送信した結果

一覧をコードから作るものが**Scramble**、一覧と実行ボタンを表示するものが**Scalar**です。
両方ともバックエンドに組み込んであるので、メンバーが別々に導入する必要はありません。

## 1. ページを開く

APIの初回起動ができていない場合は、[バックエンド担当のIssue #2](https://github.com/IH-Ggroup/minetenant-backend/issues/2)の①〜②を先に進めてください。

1. VS Codeで`minetenant-backend`フォルダを開く。
2. 「ターミナル」→「新しいターミナル」をクリックする。
3. 以前からクローンしてある場合は、[Issue #2](https://github.com/IH-Ggroup/minetenant-backend/issues/2)の①「クローン済みの場合」に従い、`git status`を確認する。`main`で変更がなければ`git pull --ff-only`を実行する。別ブランチや変更がある場合はリーダーと確認する。
4. 最新のコードを受け取ったら、次を実行する。

```text
composer install
```

5. APIを起動する。すでに起動していれば、該当ターミナルで`Ctrl+C`を押してから再起動する。

```text
php artisan serve --host=127.0.0.1 --port=8787
```

6. [API一覧・動作確認](http://localhost:8787/docs/api)をクリックする。

**「MineTenant API一覧・動作確認」と、左側の機能メニューが見えれば成功です。**
このリンクは、APIを起動しているPCのブラウザで開いてください。

## 2. まずは起動確認を送る

1. 左の **「動作確認」** の矢印を押す。
2. **「APIの起動を確認する」** をクリックする。
3. **`Test Request`** を押す。APIに送信する画面が開く。
4. 上にある **`Send`** を押す。
5. **`Response`** のステータスが **`200 OK`**、本文が **`MineTenant API is running.`** なら成功。
6. 実行画面の右上の閉じるボタン（`Close Client`）で、一覧に戻る。

一覧側の「STATUS: 200」などは**仕様に書かれた例**です。
実際に動いたかは、**Sendを押した後のResponse**で確認してください。

## 3. 商品と在庫を見る

1. 左の **「商品」→「商品1件の詳細を見る」** をクリックする。
2. **`Test Request`** を押す。
3. `Path Parameters`の **`product`** の値が **`product-stool`** になっていることを確認する。違っていたら書き換える。
4. **`Send`** を押す。
5. `Response`の本文で、`data`の中の`stock`を探す。これが今の在庫。
6. 購入を試す前に、在庫の数字をメモする。新しいデモDBなら`2`。

`GET`はデータを読む操作です。商品や在庫は変わりません。

## 4. ログインする

### ログインの準備

1. 実行画面を閉じ、左の **「認証」→「CSRF Cookieを準備する」** をクリックする。
2. **`Test Request` → `Send`** を押す。
3. **`204 No Content`** なら成功。本文が空で大丈夫。

### デモ購入者でログイン

1. 実行画面を閉じ、**「ログインする」→ `Test Request`** を開く。
2. **`Request Body`（送信する本文）** の欄を開き、内容を確認する。`Raw`表示なら以下のJSONにする。

```json
{
  "email": "demo@minetenant.jp",
  "password": "password"
}
```

3. **`Send`** を押す。
4. **`200 OK`** と **`"id": "user-buyer"`** が返れば成功。
5. 実行画面を閉じ、**「ログイン中の自分を確認する」→ `Test Request` → `Send`** でも同じユーザーが返ることを確認する。

**Authentication欄への入力は不要です。** この画面がCookieとCSRFヘッダーを自動送信します。
他のタブへ移っても、同じブラウザ・同じ`localhost`で操作してください。

## 5. 商品を1回購入する

この操作は開発用DBの在庫・履歴を更新します。商品`product-stool`の在庫が1以上あることを確認してから進めてください。

1. 実行画面を右上の閉じるボタン（`Close Client`）で閉じ、左の **「Web購入」→「商品IDを本文に入れて購入する」** をクリックする。
2. **`Test Request`** を押す。
3. **`Request Body` → `Raw`** を開き、内容を全部選択して次に置き換える。

```json
{
  "productId": "product-stool",
  "requestId": "docs-web-stool-001"
}
```

4. **`Send`を1回押す。**
5. 初回なら **`201 Created`**。返った **`data.id`** をメモする。これが取引ID。
6. 実行画面を閉じ、手順3の商品詳細APIを再度実行し、`stock`が1つ減ったことを確認する。

`requestId`は「この購入操作の番号」です。同じ購入を再送するときは、同じ値を使います。
すでにこの例を実行済みなら初回から200が返ります。新しく1個買うと決めたときだけ、別の番号を使ってください。

### 同じ購入を再送したら？

実行画面を閉じ、もう一度「Web購入」→「商品IDを本文に入れて購入する」→`Test Request`を開きます。
上と同じ商品・同じ`requestId`のまま送信すると、**`200 OK`と最初と同じ取引ID**が返ります。
在庫はさらに減りません。商品詳細をもう一度取得して確認してください。

## 6. ログアウトする

1. 実行画面を閉じ、**「認証」→「ログアウトする」→ `Test Request` → `Send`** を押す。
2. **`204 No Content`** なら成功。
3. 実行画面を閉じ、「ログイン中の自分を確認する」をもう一度送ると **`401 Unauthorized`**。ログアウトしたので正常です。

## 困ったとき

| 表示 | 確認すること |
| --- | --- |
| ページを開けない | APIのターミナルが動いているか。8787番のURLを開いているか |
| 一覧が404 | この変更を取り込んで`composer install`したか。APIを再起動したか |
| 一覧が403 | `.env`の`APP_ENV=local`を確認。設定変更後は`php artisan config:clear`とAPI再起動 |
| 一覧が白い／表示されない | インターネット接続を確認。Scalarの表示用ファイルをCDNから読み込みます |
| APIから401 | ログインの手順を実行する |
| APIから403 | 他人の店舗・商品・取引を操作していないか |
| APIから419 | CSRF Cookieの準備→ログインをやり直す。購入の再送では同じrequestIdを使う |
| APIから422 | Responseの`errors`を見て、入力する値を確認する |
| APIから409 | 在庫切れ・同じ番号を別の購入へ使っていないか、本文を確認する |

メンバーに相談するときは、**APIの名前・入力した内容・実際のステータス・返答の本文**を伝えると調べやすくなります。
Cookieやパスワードを含むヘッダー全体を貼る必要はありません。
